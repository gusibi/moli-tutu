# Spec: Moli TuTu 全量迁移到 mygo 原生桌面应用

- Status: ready-for-agent
- New code root: `mygo-app/`
- Target framework: mygo v0.8.x（实现时锁定精确版本）
- Target Go: 1.27.3+
- Platforms: macOS 12+、Windows 10+、Linux（GTK 3 / OpenGL）

## Problem Statement

Moli TuTu 目前是 Tauri 2 + React 的桌面应用，界面运行在系统 WebView 中。用户希望保留现有的全部能力，但把整个应用重写为真正的 native 桌面应用：不启动 WebView、不使用 HTML/JavaScript、不做前端构建，以换取更快的启动、更低的内存占用、更好的系统集成，以及消除现有 WebView 与 IPC 带来的性能损耗。

现有应用的功能必须完整保留，包括：拖拽、文件选择、剪贴板、URL 四种上传入口；14 种存储提供方；上传历史与哈希去重；图片压缩与压缩历史；多套存储配置及旧格式迁移；本地 HTTP 上传代理；中英切换；明暗主题；跨平台安装包。迁移还不能把现有缺陷带过去，例如未注册的历史清理命令、无效的压缩高级选项、只处理第一个文件的多选上传、把图片字节转成 JSON 数组再走 IPC 的低效上传路径。

用户还要求新代码放在一个独立目录中，与现有 Tauri 代码并存，便于逐步迁移、并行验证和随时回滚。

## Solution

在独立目录 `mygo-app/` 中新建一个纯 Go 的 mygo 应用，使用 mygo 的原生 UI（`ui.View`）绘制全部界面，不创建任何 WebView。新应用作为现有 Moli TuTu 的完整替代品，覆盖当前所有用户可见功能，并在首次启动时自动迁移 Tauri 版本的配置、设置与上传历史。

迁移采取“并行开发、完整交付、一次性切换”的方式，而不是只做一个 PoC：

1. 新应用独立构建、独立打包、独立发布 beta。
2. 旧 Tauri 应用在 beta 期间继续发布，作为回滚路径。
3. 新应用达到功能对等、通过跨平台验收后，替换正式发布包。
4. 旧代码在切换完成后保留一个版本周期，再决定删除。

新应用继续沿用现有应用名称、标识符、图标、配置 JSON 结构和上传历史数据库结构，确保用户数据、权限和发布渠道尽可能平滑地延续。

## User Stories

### 启动、窗口与系统集成

1. 作为桌面用户，我希望应用启动后直接显示原生窗口，而不是先启动 WebView，这样启动更快、内存占用更低。
2. 作为 macOS 用户，我希望窗口使用系统红绿灯和原生拖动区域，这样它看起来和用起来都像原生 Mac 应用。
3. 作为 Windows 用户，我希望窗口、菜单和安装程序符合 Windows 习惯，这样我不需要学习一套陌生的交互。
4. 作为 Linux 用户，我希望应用能在 GTK 3 桌面上正常启动和缩放，这样我的现有环境不需要额外配置。
5. 作为返回用户，我希望应用记住窗口大小、位置、主题和语言，这样我不必每次重新设置。
6. 作为小屏幕用户，我希望窗口有合理的最小尺寸，内容可以滚动，这样所有控件仍然可用。
7. 作为键盘用户，我希望用 Tab、Enter、Escape 和方向键完成导航、确认和取消，这样我可以不用鼠标操作。
8. 作为使用读屏软件的用户，我希望按钮、输入框、表格、对话框都有正确的名称、角色和状态，这样我能理解并操作界面。
9. 作为用户，我希望应用有原生菜单（关于、偏好设置、编辑、窗口、退出），这样我能使用系统级快捷键和标准操作。
10. 作为用户，我希望关闭窗口、退出应用和重新打开时行为稳定，不出现残留进程或数据损坏。

### 上传

11. 作为用户，我希望把一张或多张图片从 Finder/Explorer 拖到上传区域，这样我可以快速上传。
12. 作为用户，我希望通过文件选择器一次选择多张图片，这样我可以批量上传。
13. 作为用户，我希望直接粘贴剪贴板中的截图，这样截图可以立刻上传。
14. 作为用户，我希望粘贴一个图片 URL，由应用下载后上传，这样我可以复用网络上的图片。
15. 作为用户，我希望非图片文件被拒绝并给出明确原因，这样我不会误传错误文件。
16. 作为用户，我希望上传前看到文件类型、大小和文件名校验结果，这样我知道哪些文件会被处理。
17. 作为用户，我希望批量上传时看到每个文件的状态和进度，这样我知道当前处理到哪一步。
18. 作为用户，我希望批量上传中某个文件失败时其余文件继续处理，这样一个小问题不会阻塞整批任务。
19. 作为用户，我希望重复图片命中本地哈希缓存时直接返回已有 URL，这样不会重复占用存储。
20. 作为用户，我希望上传成功后可以一键复制 URL，这样我可以直接粘贴到 Markdown 或聊天窗口。
21. 作为用户，我希望 URL 上传能处理重定向、Content-Type、文件名推导和 HTTP 错误，这样链接上传可靠。
22. 作为用户，我希望上传在后台线程执行，窗口保持响应，这样大图上传时界面不会卡住。
23. 作为用户，我希望没有配置存储时看到明确提示，并能一键跳到设置页，这样我能快速修复。
24. 作为用户，我希望上传失败时看到可操作的错误信息（网络、鉴权、桶不存在、权限不足等），这样我知道该改什么。
25. 作为用户，我希望大图上传不再经过 JSON 数字数组的 IPC 序列化，这样上传速度和内存占用明显改善。

26. 作为用户，我希望上传页显示最近上传的图片和“查看全部”入口，这样我不切页也能确认刚才的结果。

### 存储配置

27. 作为用户，我希望添加多套存储配置，这样我可以在 R2、S3、Imgur、GitHub 等之间切换。
28. 作为用户，我希望从 14 种提供方中选择：Cloudflare R2、AWS S3、Backblaze B2、DigitalOcean Spaces、MinIO、Wasabi、阿里云 OSS、腾讯云 COS、七牛云 Kodo、自定义 S3、Imgur、SM.MS、GitHub、又拍云。
29. 作为用户，我希望配置表单根据提供方显示对应字段，这样我不会看到无关选项。
30. 作为用户，我希望必填字段有校验，缺失时不能保存，这样不会产生半成品配置。
31. 作为用户，我希望把某一套配置设为当前启用，这样后续上传使用它。
32. 作为用户，我希望编辑和删除配置，删除当前配置时自动切换到下一套可用配置。
33. 作为用户，我希望密码和 Token 在界面上被遮蔽，这样旁人不会直接看到敏感信息。
34. 作为用户，我希望旧的 `config.json`（包括单配置格式和旧 R2 格式）自动迁移，这样我不需要重新输入密钥。
35. 作为用户，我希望保存配置后立即初始化上传器并应用，不需要重启应用。
36. 作为用户，我希望配置初始化失败时看到具体错误，而不是静默失败。
37. 作为用户，我希望配置文件继续使用原有 JSON 字段名和结构，这样旧版本和新版本可以互相读取。

### 上传历史

38. 作为用户，我希望历史页显示缩略图、文件名、大小、时间和操作按钮，这样我能快速找到上传过的图片。
39. 作为用户，我希望按文件名搜索历史，这样记录多时也能定位。
40. 作为用户，我希望历史分页或虚拟化显示，这样 100 条记录仍然流畅。
41. 作为用户，我希望点击缩略图预览大图，这样我能确认图片内容。
42. 作为用户，我希望复制历史记录的 URL，这样我能再次使用。
43. 作为用户，我希望在浏览器中打开图片，这样我能检查原始资源。
44. 作为用户，我希望通过系统保存对话框下载图片，这样我能保留本地副本。
45. 作为用户，我希望删除单条历史记录，并在删除前确认，这样我不会误删。
46. 作为用户，我希望清空全部历史记录，并在清空前确认，这样我能重置记录。
47. 作为用户，我希望历史记录在重启后仍然存在，这样数据不会丢。
48. 作为用户，我希望远程缩略图加载失败时显示占位图，而不是破图或空白。
49. 作为用户，我希望历史记录最多保留 100 条，这样数据库不会无限增长。
50. 作为用户，我希望历史列表的缩略图异步加载并缓存，这样滚动时不会反复请求网络。

### 图片压缩

51. 作为用户，我希望拖拽、选择或粘贴图片到压缩页，这样我可以压缩本地图片。
52. 作为用户，我希望选择 JPEG、PNG、WebP 输出格式，这样我能在兼容性和体积之间取舍。
53. 作为用户，我希望调整 JPEG/WebP 质量，这样我能控制压缩程度。
54. 作为用户，我希望使用 100%、75%、50%、25% 和自定义尺寸缩放，这样我能快速调整分辨率。
55. 作为用户，我希望锁定宽高比，这样图片不会变形。
56. 作为用户，我希望看到压缩前后的左右对比预览，并能拖动分割线，这样我能判断质量。
57. 作为用户，我希望看到原始大小、压缩后大小和压缩比例，这样我知道节省了多少空间。
58. 作为用户，我希望把压缩结果保存到本地，使用系统保存对话框选择路径，这样我能保留文件。
59. 作为用户，我希望把压缩结果直接上传到当前图床，这样我能快速分享。
60. 作为用户，我希望压缩历史保留最近 10 条，这样我能回看之前的处理。
61. 作为用户，我希望从压缩历史恢复一条记录，继续调整参数，这样我能重新压缩。
62. 作为用户，我希望删除单条压缩记录或清空全部记录，并同时清理磁盘上的临时文件，这样不会浪费空间。
63. 作为用户，我希望高级选项（预乘 Alpha、线性 RGB、PNG 调色板、抖动）真正生效，而不是只有 UI 没有效果。
64. 作为用户，我希望照片按 EXIF 方向自动转正，这样手机照片不会横着显示。
65. 作为用户，我希望压缩在后台执行并显示处理中状态，这样界面不会冻结。
66. 作为用户，我希望压缩失败时看到明确原因（格式不支持、内存不足、图片损坏等），这样我知道怎么办。
67. 作为用户，我希望 AVIF 选项的行为与当前版本一致或明确标注限制，这样我不会被误导。

### 本地 API 代理

68. 作为用户，我希望开启一个仅监听 `127.0.0.1` 的 HTTP 上传接口，这样其他脚本或工具可以通过本应用上传图片。
69. 作为用户，我希望设置并校验代理端口，默认 38123，这样我可以避开端口冲突。
70. 作为用户，我希望看到代理运行状态和完整端点地址，这样我能配置外部工具。
71. 作为用户，我希望代理复用当前启用的存储配置和哈希缓存，这样行为与应用内上传一致。
72. 作为用户，我希望代理在应用重启后按上次设置自动启动，这样我的自动化流程不中断。
73. 作为用户，我希望端口被占用或没有存储配置时看到明确错误，这样我能修复。
74. 作为用户，我希望停止代理后端口立即释放，这样我可以切换端口或退出应用。

### 主题、语言与反馈

75. 作为用户，我希望选择浅色、深色或跟随系统主题，这样应用外观符合我的偏好。
76. 作为用户，我希望在中文和英文之间切换，所有界面文案、错误和对话框都同步更新。
77. 作为用户，我希望主题和语言选择在重启后保留。
78. 作为用户，我希望成功、失败、提示信息以 Toast 形式出现，并在几秒后自动消失。
79. 作为用户，我希望删除、清空、覆盖等破坏性操作有确认对话框，这样我不会误操作。
80. 作为用户，我希望应用使用系统强调色、字体和缩放设置，这样它和桌面环境一致。
81. 作为用户，我希望在减少动态效果、高对比度等辅助功能设置下仍然可用。

### 数据迁移与兼容

82. 作为现有用户，我希望新应用首次启动时自动迁移 `config.json`、`settings.json` 和 `uploads.db`，这样我不需要重新配置或丢失历史。

84. 作为现有用户，我希望迁移是幂等的，多次启动不会重复复制或覆盖新数据。
85. 作为现有用户，我希望旧应用仍在运行时收到明确提示，避免数据库被占用导致迁移失败。

87. 作为现有用户，我希望新应用继续使用相同的应用名称、标识符和图标，这样系统权限、开机项和用户认知保持连续。
88. 作为现有用户，我希望新版本能读取旧版本的配置和数据库，这样 beta 与正式版之间可以来回切换。

## Implementation Decisions

### 1. 新代码目录与模块边界

- 新应用全部代码放在仓库根目录的 `mygo-app/` 中，作为独立的 Go module，不与现有 Tauri 前端或 Rust 后端共享构建配置。
- `mygo-app/` 内按职责拆分包：应用状态与视图、服务接口与实现、存储提供方、配置与数据库、图片管线、HTTP 代理、数据迁移、国际化资源、打包资源。
- 现有 `src/`、`src-tauri/`、`package.json` 和 Tauri 配置在迁移期间保持不变，继续产出旧版本安装包。
- 新应用的可执行文件名保持 `moli-tutu`，应用显示名保持 `Moli Tu Tu`，应用标识符保持 `com.gusi.moli-tutu`。
- 新应用只使用 mygo 的原生 UI 能力，不创建 WebView，不加载 HTML，不引入前端构建链。

### 2. 技术基线

- 使用 Go 1.27.3 或更高版本；当前开发机是 Go 1.26.4，实施前必须升级。
- 锁定 mygo 的精确版本（以实施开始时的最新 v0.8.x 为准，建议 v0.8.3），并在 `go.mod` 中固定；升级 mygo 作为独立变更，附带完整测试和跨平台冒烟。
- 保持纯 Go、无 cgo，确保可以从 macOS 交叉编译 Windows 和 Linux 产物。
- WebP 编码使用 cgo-free 的 libwebp WASM/transpiled 实现，并启用 `nodynamic` 构建标签，避免依赖用户机器上是否安装 libwebp。
- SQLite 使用纯 Go 驱动 `modernc.org/sqlite`，不使用 cgo 版本的 SQLite。
- 平台基线为 macOS 12+、Windows 10+、Linux GTK 3 + OpenGL；不再支持 macOS 10.13/10.14。

### 3. 唯一测试缝

- 整个应用只引入一个高层测试缝：视图依赖一个 `Service` 接口，所有业务操作和平台副作用都通过它进入。
- `Service` 覆盖：配置读取/保存/删除/切换、上传（字节、URL、剪贴板）、历史读取/删除/清空、压缩、压缩历史、代理状态/启停、选择文件、保存文件、复制文本、打开 URL、读取剪贴板图片。
- 生产实现包装 mygo 的对话框、剪贴板、Shell、窗口更新等 API；测试实现是一个内存 fake，不弹系统对话框、不访问网络、不写真实用户目录。
- 视图测试只通过 `ui.NewTester` 操作界面并断言用户可见结果，不直接调用包内私有函数，也不依赖真实文件系统。
- 服务层集成测试使用临时目录、内存 HTTP 服务和假 S3 端点，验证真实实现的外部行为。
- 这是本 spec 约定的唯一测试缝。如果实现时发现必须在视图内部再开第二个缝，先修改本节并说明原因，再写代码。

### 4. 应用状态与页面

- 应用状态集中在一个顶层状态对象中，包含：当前页面、配置列表与活动配置、上传历史、压缩状态与压缩历史、代理状态、主题、语言、Toast 队列、缩略图缓存、窗口引用。
- 页面固定为五个：上传、上传历史、图片压缩、压缩历史、设置；侧边栏显示应用图标和名称、五个导航项，以及语言和主题切换；设置页包含语言、主题、代理和存储配置。
- 上传页在拖拽区下方展示最近 10 条上传记录和“查看全部”入口；历史页负责完整列表、搜索和分页。
- 视图函数只根据状态绘制界面，不做阻塞 I/O；所有网络、磁盘、压缩、代理操作在后台 goroutine 中执行，完成后通过窗口的 `Update` 回到主线程修改状态并重绘。
- 视图重建是每帧行为，不能把解码图片、读文件、发请求等重操作放在视图函数中；缩略图和预览图必须走缓存。
- 状态共享使用互斥锁保护；视图读取快照，避免在绘制过程中被后台 goroutine 修改。
- 上传和压缩任务需要支持“进行中”状态、逐文件状态和错误信息；批量上传使用有限并发（默认 3），避免打满网络和内存。
- 所有破坏性操作使用确认对话框；所有成功/失败/提示使用 Toast；错误信息按当前语言显示。

### 5. 数据模型与持久化

- 继续使用现有 JSON 字段名和结构：`StorageConfig`、`StorageConfigList`、`AppSettings`、`UploadRecord`、`UploadResult`、`ApiProxyStatus` 保持兼容，避免旧配置文件无法读取。
- 配置继续保存在 `config.json`，设置继续保存在 `settings.json`；支持从旧 R2 单配置、旧单 `StorageConfig` 和新 `StorageConfigList` 三种格式迁移。
- 上传历史继续使用 SQLite 的 `uploads` 表，字段保持 `id`、`original_filename`、`file_hash`、`file_size`、`url`、`upload_time`；保留 `file_hash` 唯一约束和按时间倒序的 100 条上限。
- 数据库启用 WAL 和合理的 busy timeout，减少后台上传、历史读取和代理并发时的锁冲突。
- 压缩历史不再使用 IndexedDB/localStorage，改为用户数据目录下的 JSON 索引加图片文件：每条记录保存原始文件、压缩文件、配置、大小、比例、时间、来源类型；最多 10 条；删除记录时同步删除文件。
- 配置文件以仅当前用户可读的权限写入；日志和错误信息不得包含 Secret Access Key、Token、密码或完整配置内容。
- 旧版 `from_cache` 没有持久化到数据库，历史页的 “Cached” 徽标实际上永远不会出现；新版本不再在历史记录中展示这个无效徽标，但上传结果仍保留 `from_cache` 字段供 Toast 使用。

### 6. 存储提供方

- S3 兼容提供方统一使用 AWS SDK for Go v2：Cloudflare R2、AWS S3、Backblaze B2、DigitalOcean Spaces、MinIO、Wasabi、阿里云 OSS、腾讯云 COS、七牛云 Kodo、自定义 S3。
- 保留现有行为：S3 兼容提供方、GitHub 和又拍云用 UUID + 原扩展名生成对象键；有 `path_prefix` 时加前缀；公开 URL 由 `public_url_base` 拼接；上传时设置正确的 Content-Type；Imgur 和 SM.MS 使用原文件名，并保留 SM.MS 重复图片返回已有 URL 的逻辑。
- 对非 AWS 端点（尤其是 localhost、IP、MinIO）使用 path-style 访问，避免虚拟主机风格在自建 S3 上失败；AWS 官方端点保持默认风格。
- Imgur、SM.MS、GitHub、又拍云使用标准库 `net/http` 实现，保留现有请求方式、鉴权头、响应解析和错误语义。
- 所有提供方共享统一的 `Uploader` 行为：校验配置、设置超时、限制响应大小、把底层错误转换为用户可读错误、返回公开 URL。
- 网络请求设置连接/请求超时；上传大文件时支持读取进度；失败时返回足够上下文，但日志中不泄露密钥。
- S3 初始化时可以执行一次轻量的桶访问检查，但检查失败只作为警告，不阻止配置保存，保持现有行为。

### 7. 图片管线

- 解码支持 JPEG、PNG、GIF（首帧）、WebP、BMP；读取 EXIF 方向并在压缩前转正，保证手机照片方向正确。
- 输出支持 JPEG、PNG、WebP；JPEG 使用标准库编码器并按质量参数映射；PNG 使用最高压缩级别；WebP 使用 cgo-free 的 libwebp 实现。
- 缩放使用高质量重采样（Catmull-Rom 或 Lanczos 近似），支持 100%/75%/50%/25% 预设和自定义宽高；支持保持宽高比。
- 高级选项必须真正生效：预乘 Alpha 影响透明像素处理；线性 RGB 影响缩放时的颜色空间；PNG 调色板减少颜色数量；抖动使用 Floyd-Steinberg 或同等算法。
- AVIF 在 v1 中不实现真正的 AVIF 编码，保持与当前版本一致的“AVIF 选项输出 WebP”行为，并在界面或更新说明中明确标注；真正的 AVIF 编码留到后续版本。
- 压缩在后台 goroutine 中执行；对超大图片设置像素数/内存上限，超限时返回明确错误，避免应用被拖垮。
- 压缩结果同时生成用于预览的位图；预览位图使用 `ui.Bitmap`，并在不再显示时释放像素，避免长时间占用内存。
- 保存压缩结果使用系统保存对话框，默认文件名为“原名_compressed.扩展名”；上传压缩结果沿用统一上传流程。

### 8. 上传流程

- 支持四个入口：拖拽文件、文件选择器、剪贴板图片、图片 URL。
- 拖拽和文件选择器支持多文件；非图片文件跳过并提示；空文件、损坏文件、超大文件给出明确错误。
- 剪贴板读取优先使用 mygo 的原生图片读取；如果剪贴板是图片文件路径或 data URL，则走兼容回退。
- URL 上传只允许 `http` 和 `https`，设置请求超时和最大响应大小，推导文件名和扩展名，处理重定向和 Content-Type 缺失。
- 上传前计算 SHA-256；命中数据库缓存时直接返回已有 URL，并在结果中标记 `from_cache`。
- 批量上传默认 3 个并发；单个文件失败不取消其他文件；所有任务结束后汇总成功/失败数量。
- 上传进度通过读取包装器上报已发送字节数；无法获得总大小时显示不确定进度。
- 上传结果写入历史数据库；数据库写入失败不应让已成功的上传变成失败，但要在日志和界面中提示。
- 上传任务可被窗口关闭或应用退出中止；退出时等待在途任务完成或安全取消，避免写坏数据库。

### 9. 历史与缩略图

- 历史页从数据库读取最近 100 条记录，支持按文件名过滤、分页（每页 10 条）或等效的虚拟化显示。
- 缩略图按 URL 异步加载：内存 LRU + 磁盘缓存；磁盘缓存放在用户缓存目录，按 URL 哈希命名，设置总大小上限和过期时间。
- 缩略图加载使用有限并发（默认 4），失败重试一次，失败后显示占位图；不得在视图函数中同步请求网络。
- 图片解码使用 `ui.DecodeBitmap` 或等效能力；位图被缓存淘汰或不再显示时释放像素，避免 GPU/CPU 内存持续增长。
- 预览大图使用独立弹层或对话框，支持复制 URL、浏览器打开、保存到本地。
- 历史删除和清空操作必须真正删除数据库记录；现有版本中未注册的 `clear_upload_history` 和 `delete_upload_record` 命令在新版本中必须实现并测试。

### 10. 压缩与压缩历史

- 压缩页在未选择图片时显示拖拽/选择/粘贴入口；选择后进入编辑视图：左侧参数面板，右侧对比预览，底部统计和操作按钮。
- 参数面板包含格式、质量、缩放预设、自定义宽高、保持宽高比、高级选项；格式为 JPEG、PNG、WebP、AVIF（AVIF 按上节处理）。
- 对比预览使用左右分割，可拖动分割线；原图和压缩图都按容器等比缩放；处理中显示“压缩中”状态。
- 压缩参数变化后自动重新压缩，使用短暂防抖；用户手动保存或上传时使用当前最新结果。
- 压缩历史最多 10 条；每条记录可预览、恢复编辑、删除；清空时删除所有关联文件。
- 旧版压缩历史保存在 WebView 的 IndexedDB 和 localStorage 中，Go 侧无法直接读取；v1 不做自动迁移，首次启动时给出一次性说明。后续可以通过旧版导出/新版导入解决。

### 11. 本地 API 代理

- 使用 `net/http` 实现 `POST /upload`，只绑定 `127.0.0.1`，默认端口 38123。
- 请求为 multipart/form-data，取第一个带文件名的文件字段；响应为 JSON，字段保持 `success`、`url`、`error`、`from_cache`。
- 代理复用当前活动存储配置、统一上传流程和 SHA-256 缓存；上传成功后写入历史数据库。
- 端口校验范围 1–65535；代理运行时不允许直接改端口，必须先停止；端口被占用、没有存储配置等情况返回明确错误。
- 开启/关闭状态和端口写入 `settings.json`；应用启动时如果设置为开启，则自动尝试启动，失败则回退为关闭并记录日志。
- 代理停止时优雅关闭监听和连接，确保端口及时释放。

### 12. 主题、语言与通知

- 主题支持跟随系统、浅色、深色三种；首次启动默认跟随系统，用户选择后持久化。
- 使用 mygo 的主题能力跟随系统强调色、字体缩放、高对比度和减少动态效果；原生控件使用主题色，不硬编码 Tailwind 颜色。
- 语言支持中文和英文，迁移现有全部文案键；新增逐文件上传状态、迁移说明、压缩高级选项等键；两种语言必须键集合一致。
- 语言切换立即生效；使用 mygo 的 locale 能力或等价机制持久化用户选择。
- Toast 用于成功、失败、提示；破坏性操作使用确认对话框；确认按钮的文案和默认焦点符合平台习惯。
- 无障碍：所有图标按钮必须有可读名称；表格、对话框、输入框、开关、滑块使用正确的角色和标签；键盘焦点顺序合理。

### 13. 数据迁移

- 首次启动时，如果新应用数据目录中不存在 `config.json`、`settings.json`、`uploads.db`，则从旧 Tauri 数据目录复制。
- 旧目录按平台解析：macOS 为 `~/Library/Application Support/com.gusi.moli-tutu`，Windows 为 `%APPDATA%\com.gusi.moli-tutu`，Linux 为 Tauri 2 对应的应用数据目录；新目录使用 mygo 的 `PathUserData`。
- 只复制、不删除旧文件；复制完成后写入迁移标记文件，记录来源、时间和版本，保证幂等。
- 如果旧应用正在运行导致数据库被占用，提示用户退出旧应用后重试；不要强行覆盖或截断数据库。
- 迁移前检查目标文件是否已存在；已存在时不覆盖，避免新版本数据被旧数据回滚。
- 复制后打开数据库并执行兼容性检查；如果表结构不兼容，保留旧文件并给出明确错误，不自动破坏性迁移。
- 主题和语言存储在旧版 localStorage 中，无法直接从 Go 读取；首次启动按系统语言和系统主题初始化，用户可重新选择。
- 压缩历史不做自动迁移；首次启动时显示一次说明，告知旧压缩记录不会出现在新版本中。

### 14. 打包、签名与发布

- 使用 mygo 的打包能力生成 macOS `.app`/`.dmg`、Windows NSIS 安装程序、Linux `.deb`/压缩包/桌面入口。
- 应用名称、标识符、版本、图标与旧版保持一致；图标使用 1024×1024 PNG，并生成各平台所需格式。
- macOS 最低版本设为 12.0；在 README、发布说明和下载页明确说明不再支持 10.13/10.14。
- macOS 产物执行签名和公证；Windows 产物预留代码签名配置；Linux 产物提供 `.deb` 和安装脚本。
- 重写 GitHub Actions：在 macOS、Windows、Linux 上运行 `go test ./...` 和构建；macOS 产出 universal 或分别产出 arm64/amd64；Windows 产出安装程序；Linux 产出 deb/tar。
- 发布流程支持 beta 标签和正式标签；beta 与旧 Tauri 版本并存；正式切换前保留旧版本下载入口至少一个版本周期。
- 不实现自动更新（当前应用也没有启用）；更新仍通过下载安装包完成。

### 15. 错误处理与日志

- 定义面向用户的错误类型，包含本地化消息和可选的技术细节；界面展示本地化消息，日志记录技术细节。
- 网络、鉴权、配置、文件系统、图片解码、数据库、代理端口等错误分别映射为可操作的提示。
- 日志写入用户日志目录，包含时间、级别、模块和错误；按大小轮转，保留有限数量文件。
- 日志不得包含 Secret Access Key、Token、密码、完整配置对象或图片内容；URL 可以记录，但查询参数中的敏感信息要脱敏。
- 未捕获的 panic 在顶层恢复并记录，尽量保证应用退出前刷新日志和数据库。

### 16. 并发与性能

- 主线程只做视图构建和轻量状态更新；网络、磁盘、压缩、缩略图解码全部在后台。
- 批量上传并发上限 3；缩略图加载并发上限 4；压缩任务串行或最多 2 个，避免内存峰值。
- 所有网络请求设置超时和上下文取消；应用退出时取消后台任务。
- 图片解码和压缩设置像素/内存上限；超限时拒绝并提示，而不是让系统 OOM。
- 缩略图缓存设置内存条目上限和磁盘容量上限；淘汰时释放位图。
- 预期收益：大图上传不再经过 JSON 数组 IPC，启动不再加载 WebView，内存占用下降；具体数值在 beta 中测量并记录。

### 17. 已知缺陷的处理决策

- 实现并测试历史删除、历史清空命令；现有版本前端调用但后端未注册。
- 移除历史列表里永远不出现的 “Cached” 徽标；上传结果仍保留 `from_cache` 供 Toast 使用。
- 真正实现压缩高级选项，不再保留只有 UI 没有效果的开关。
- 文件选择器支持多选并真正上传全部文件，而不是只取第一个。
- 保留 100 条上传历史、10 条压缩历史的上限。
- 保留现有 14 种提供方和字段结构；不新增提供方。
- 保留现有 API 代理端点、端口和 JSON 响应格式。

## Testing Decisions

- 好的测试只验证外部行为：用户看到什么、服务返回什么、磁盘上留下什么，不验证私有函数、内部状态字段或具体实现步骤。
- 最高测试缝是 `Service` 接口。视图测试使用 fake service，服务测试使用真实实现 + 临时目录/HTTP 假服务。除这个缝外不再为测试新增第二套抽象。
- 视图测试使用 mygo 的 `ui.NewTester`，按文本或无障碍名称查找控件，模拟点击、输入、键盘和滚动，断言界面文本、Toast、对话框和状态。参考 mygo 的 `counter-native` 示例测试。
- 服务层测试覆盖：配置 CRUD 与活动切换、旧配置迁移、上传缓存命中、批量上传部分失败、历史 100 条上限、删除/清空、压缩历史 10 条上限、代理启停与端口冲突。
- 存储提供方测试使用 `httptest` 假服务：S3 兼容端点、Imgur、SM.MS、GitHub、又拍云分别验证请求方法、鉴权头、路径、Content-Type、请求体和响应解析；不访问真实网络。
- 图片管线测试使用固定的 JPEG/PNG/WebP/EXIF 样本，断言输出格式、尺寸、方向、透明通道、调色板颜色数和压缩后大小范围；不做逐像素 golden 对比，避免编码器差异导致脆弱测试。
- 数据库和迁移测试使用临时目录：构造旧版三种配置格式、旧 `uploads.db` 和已存在的目标文件，验证复制、幂等、冲突和错误路径。
- 代理测试使用随机端口或可注入监听器，验证 multipart 上传、缓存命中、无存储配置、端口占用和响应 JSON。
- 国际化测试断言中英文键集合一致、没有缺失或多余键；新增文案必须同时更新两种语言。
- 打包冒烟测试在 CI 中执行跨平台构建；macOS 额外验证 `.app` 可启动，Windows 验证安装程序生成，Linux 验证 deb/tar 生成。
- 测试不依赖真实用户目录、真实密钥、真实图床或网络；所有外部依赖必须可注入或可替换。

## Out of Scope

- iOS/Android 移动端；mygo 是桌面框架。
- 真正的 AVIF 编码；v1 保持当前“AVIF 输出 WebP”的行为并明确标注。
- 自动更新机制；当前应用未启用，继续通过安装包更新。
- 托盘图标/菜单栏常驻模式；当前应用没有，v1 不新增。
- Linux AppImage；mygo 产出 deb/tar/PKGBUILD，足够覆盖当前 Linux 发布。
- 从旧版 IndexedDB/localStorage 自动迁移压缩历史、主题和语言；只迁移配置文件、设置和上传历史。
- 云同步、账号系统、团队协作、图片管理后台。
- 图片裁剪、旋转、滤镜等编辑功能；当前只有压缩。
- S3 分片上传/断点续传；保持当前单次 PUT 行为。
- 与旧版逐像素一致的视觉还原；native 控件外观会变化，但布局、信息和操作保持一致。
- Windows 代码签名证书和 Apple 公证凭据的采购；CI 只负责使用已有凭据。
- 在同一个发布版本中删除旧 Tauri 代码；切换完成后再单独清理。
- 当前应用没有的新功能，除了批量上传、进度、真实高级压缩选项等明确的缺陷修复。

## Further Notes

- mygo 仍处于 0.x（当前 v0.8.3），API 可能变化。所有 mygo 调用应集中在少量适配层中，升级时只改适配层和测试，不把框架细节散落到业务代码。
- 实施前先把开发机 Go 升级到 1.27.3+；CI 也固定同一版本。
- macOS 最低版本从 10.13 提升到 12.0，是本次迁移唯一的明确平台回退；发布前需要确认用户分布并提前公告。
- 新旧应用的数据目录规则不同：旧版按 identifier，新版按应用显示名；迁移必须按平台分别解析，不能写死单一绝对路径。
- 压缩历史无法自动迁移是已知的用户体验损失；如果用户强烈需要，后续在旧版加“导出压缩历史”，新版加“导入”即可。
- 建议在 beta 中记录以下指标：冷启动时间、空闲内存、100 条历史滚动帧率、10MB 图片上传耗时、JPEG/PNG/WebP 压缩耗时和产物大小、安装包体积。与 Tauri 版本对比后再决定正式切换。
- 功能对等验收以本 spec 的 User Stories 为准；每条 story 在实现时对应至少一个自动化测试或手动验收项。
- 旧 Tauri 应用在 beta 期间继续发布；正式切换后保留至少一个版本的旧安装包和回滚说明。
- 当前仓库没有统一的 issue tracker 标签约定；发布本 spec 时使用 GitHub Issues 和 `ready-for-agent` 标签。如果团队使用其他 tracker，需要先同步标签词汇。

## Implementation Notes

These notes record decisions made while implementing the first full pass:

- The S3-compatible uploader uses a small in-tree AWS Signature Version 4 signer instead of the AWS SDK for Go. The app only needs `PutObject`, and avoiding the SDK keeps the binary and cross-compilation simple. The wire format, headers and public URL behavior stay compatible.
- Upload history still uses the existing SQLite `uploads` table through `modernc.org/sqlite`, so old `uploads.db` files can be migrated by copying.
- The single testing seam is implemented as the `service.Service` interface. `internal/app` tests use an in-memory fake; package tests exercise the real store, uploaders, proxy and image pipeline.
- The first implementation keeps the old data path compatibility by discovering the Tauri directory from the app identifier. New data lives under mygo's `PathUserData`.
- The AVIF option continues to encode WebP, matching the previous app's actual behavior. This remains a documented limitation rather than a silent regression.

- User-facing strings are written as inline bilingual pairs (`中文`, `English`) rather than a keyed catalog. Every call supplies both languages, so parity is structural; the view tests exercise the language toggle. If the project later needs translators or generated catalogs, the pairs can be extracted into keys without changing behavior.
- Uploads report byte progress through the storage driver's progress reader; the UI throttles redraws to roughly eight per second.
- Remote thumbnails are fetched and disk-cached by the service (seven-day freshness, a 200-file prune) so the view still has no direct network or disk access.
- Logs rotate at 5 MiB with three files under mygo's `PathLogs`.
- Compression history is recorded when the user saves or uploads a compressed image, not on every slider tick, so the ten-record history stays useful.
- A one-time toast explains the old WebView compression history was not migrated.
- A new `mygo-native` GitHub Actions workflow runs tests and builds macOS, Windows and Linux artifacts; production signing/notarization secrets still need to be supplied by the maintainer.
